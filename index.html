Mapkeeper

A router for Graphify, spec-kit, and security-audit. Mapkeeper detects the providers, hands off to their native skills and commands, and links their outputs — without reimplementing any of them.

Router + local state

Mapkeeper does not build graphs, run audits, or execute specs. Start with the provider's own command, then use mapkeeper status and mapkeeper links for provenance and cross-references.

Overview

Source

Mapkeeper is a router and cross-reference layer. Graphify owns the graph, spec-kit owns the specs, and security-audit owns the audit. Mapkeeper detects them, hands off, records local provenance, and links their native outputs.

Never reimplement a provider. No graph projection, vault, architecture export, coverage ledger, findings ingestion, or spec execution.

Start here

Only show this menu when the invocation has no task or arguments, for example /mapkeeper. If the user already asked for something, skip the menu and act.

Check once, without scanning the repo:

  • graphify-out/graph.json — Graphify cache present?
  • .specify/ — spec-kit initialized?
  • .mapkeeper/state.json — last recorded security run?
  • project-map/graph.json — legacy v2 map?

Recommend Update when a Graphify cache exists, Build when it does not, and surface a recorded security run.

#ChoiceProviderWhat happens
1Map codebaseGraphifyBuild, update, query, or open the native report
2Spec-driven workspec-kitShow feature state, then hand off the exact /speckit.* command
3Security reviewsecurity-auditGuidance, full audit, or use an existing run
4Combine outputsMapkeeperGenerate or publish the cross-reference link report
5Status & healthMapkeeperDetect providers, versions, artifacts, staleness, legacy maps

Submenus:

  • 1 Map codebase → Build (/graphify), Update (/graphify --update), Query (/graphify query "<question>"), Open graphify-out/GRAPH_REPORT.md or the HTML view.
  • 2 Spec-driven work → Status, Specify, Plan, Tasks, Analyze, Implement. Print the exact command from the detected command dir (/speckit.specify …, /speckit.plan, …). If no commands are installed, print specify init guidance and stop.
  • 3 Security review → Guidance (default), Full audit (requires an explicit output directory outside the target and confirmation), or Use an existing run (record its path for links).
  • 4 Combine outputs → Generate links, show unresolved gaps, publish with --out <path>.
  • 5 Status & health → mapkeeper status, --json, --check, legacy warning.

If a provider is missing, print its install/setup hint and continue with the others. Never install or modify a provider.

Rules

  • A provider is never reported as used unless it ran and its output parsed.
  • Never build a full Graphify graph or run a security audit without an explicit request. Prefer --update when a cache exists.
  • Spec-kit is handoff-only. Do not read and execute speckit.*.md inside a Mapkeeper turn.
  • Never publish a security candidate with verdict rejected, and never add severity to needs_validation.
  • Local artifacts only:
  • .mapkeeper/state.json — provider paths, versions, revisions, last run
  • .mapkeeper/links.{json,md} — optional cross-reference report
  • Do not write project-map/ or any graphify-out//.specify/ content.
  • Legacy project-map/ trees are read-only history; report them, never rewrite them.
  • Link reports contain fingerprints, file paths, requirement/task IDs, severities, and verdicts only — no finding titles, descriptions, or absolute run paths.

Status

mapkeeper status [--json] [--check]

If the mapkeeper bin is not installed, run the CLI from the skill checkout: node scripts/mapkeeper.mjs status.

Detects providers, versions, native artifact paths, staleness, and legacy maps. --check exits non-zero only when a present artifact is unreadable or invalid.

Links

mapkeeper links [--run <dir>] [--graph <path>] [--no-security] [--out <path>] [--check]

If the bin is unavailable, use node scripts/mapkeeper.mjs links from the skill checkout.

Reads native outputs only:

LinkFrom → to
finding_filefinding fingerprint → file path, with matching Graphify node IDs
finding_requirementfinding fingerprint → FR-### / NFR-###
requirement_taskrequirement → task
task_filetask → file
requirement_filerequirement → file (derived through tasks)

Partial inputs are allowed; missing providers are reported, never invented. --check exits non-zero when a real link target is missing (file, node, requirement, task), not when an optional provider is absent.

Install

Source

Read the guide · Source

Mapkeeper is a router for three providers:

  • Graphify — codebase knowledge graph, queries, reports
  • spec-kit — specifications, plans, tasks, and their command workflow
  • security-audit — sandboxed security reviews and findings

Each provider already does its job well. Mapkeeper does not rebuild a graph, vault, coverage ledger, or audit. It detects the providers, hands off to their native skills and commands, records local provenance, and links their outputs when asked.

Requirements

  • Node.js 20+ for the local CLI (status, links).
  • Any subset of the three providers. None is a hard dependency.
  • Optional: Kilo for the /mapkeeper slash command and skill invocation.

npx skills add https://github.com/MIQBALHAKIM/Mapkeeper --skill mapkeeper

Router and CLI

Source

Mapkeeper v3 has two surfaces: the /mapkeeper menu that routes to providers, and a small local CLI for status and links.

/mapkeeper menu

#ChoiceRoutes to
1Map codebaseGraphify: build, update, query, open report
2Spec-driven workspec-kit: status, specify, plan, tasks, analyze, implement

With arguments, skip the menu:

InputAction
/mapkeeper map [args]Invoke the Graphify skill unchanged
/mapkeeper spec <action>Print the exact /speckit.<action> command

/mapkeeper status [args]Detect providers and artifacts
/mapkeeper helpRouter reference

The command lives at ~/.config/kilo/command/mapkeeper.md (user) or .kilo/command/mapkeeper.md (project). It is plain Markdown with frontmatter.

CLI

# from the skill checkout
node scripts/mapkeeper.mjs status
node scripts/mapkeeper.mjs links

# or after installing the bin
mapkeeper status
mapkeeper links
CommandPurpose
statusDetect providers, versions, native artifacts, staleness, legacy maps

status

mapkeeper status [--json] [--check] [--dir <path>] [--no-write]
  • Refreshes .mapkeeper/state.json by default; --no-write keeps it read-only.
  • --check exits 1 only when a present artifact is unreadable or invalid.
  • Absent providers are warnings, not failures.

links

mapkeeper links [--run <dir>] [--graph <path>] [--no-security]
                [--out <path>] [--json] [--check] [--dir <path>] [--no-write]
  • --run records an existing security run (default: last recorded run).
  • --graph overrides graphify-out/graph.json.
  • --no-security omits findings from the report.
  • --out publishes a shareable Markdown copy; local JSON and Markdown always go to .mapkeeper/.
  • --check exits 1 when a linked target is missing or an input is malformed.

Examples

# after Graphify builds a cache
mapkeeper status
mapkeeper links

# combine all three providers
mapkeeper links --run ~/security-audit-skill/app/run-2

# hand off a spec action (printed by /mapkeeper spec plan)
/speckit.plan

# publish a report for a PR
mapkeeper links --out docs/mapkeeper-links.md

Exit codes

CodeMeaning
0success, including warnings and partial inputs
1--check blocking gaps, no inputs, or a requested run is missing
2usage error

Removed in v3

init, sync, audit, full, export, context, graph, specs, security, migrate, and query are owned by the providers. Use /graphify, /speckit.*, the security-audit skill, or graphify query directly. Legacy MAPPER … verbs are gone.

Graphify

Source

Graphify owns the codebase graph. Mapkeeper only detects it, hands off, and reads its native JSON for links.

Detection

  • Skill: graphify under .kilo/skills, .agents/skills, .claude/skills, .github/skills, or the matching global skill dirs.
  • CLI: graphify --version.
  • Cache: graphify-out/graph.json; report graphify-out/GRAPH_REPORT.md; vault graphify-out/obsidian/.

State records skill, skill_dir, cli, version, cache, cache_mtime, report, obsidian.

Handoff

Invoke the graphify skill with the user's arguments. Do not reconstruct its commands.

IntentHandoff
Build/graphify (or /graphify <path>)
Update/graphify <path> --update — prefer when a cache exists
Query/graphify query "<question>" (--dfs, --budget optional)
Path / explanation/graphify skill's path/explain modes
Obsidian/graphify <path> --obsidian (graphify owns the vault)
Graph database export/graphify <path> --neo4j or --falkordb
Agent access/graphify <path> --mcp

Rules

  • Never project Graphify nodes into a Mapkeeper graph.
  • Never write an Obsidian vault, HTML view, or architecture export for Graphify.
  • Never run a full build without an explicit request; --update is the default suggestion when graphify-out/graph.json exists.
  • Never claim Graphify ran unless its output parsed.
  • If the skill is missing but a cache exists, links can still read the cache; print the install hint for build/query operations.

Links input

graphify-out/graph.json nodes with id and source_file. Mapkeeper maps normalized relative file paths to node IDs for finding_file links. It does not use labels, communities, or inferred edges.

spec-kit

Source

spec-kit owns specifications, plans, tasks, and its command workflow. Mapkeeper detects it, shows feature state, and hands off the exact slash command.

Detection

  • CLI: specify on PATH; version when specify --version works.
  • Project: .specify/; active feature from .specify/feature.json (feature_directory, feature_dir, directory, path, feature) or the newest specs/*/spec.md.
  • Commands: speckit.*.md in the first matching directory:

.kilo/commands, .kilo/command, .claude/commands, .github/prompts, .cursor/commands, .windsurf/workflows, .opencode/command, .gemini/commands, .codex/prompts, .qwen/commands.

  • Hooks: .specify/extensions.yml.

State records cli, version, initialized, feature_dir, feature_mtime, commands_dir, commands, hooks.

Handoff

Print the exact command; do not read or execute the command template.

ActionCommand
Specify/speckit.specify <description>
Clarify/speckit.clarify
Plan/speckit.plan
Tasks/speckit.tasks
Analyze/speckit.analyze
Checklist/speckit.checklist
Implement/speckit.implement
Constitution/speckit.constitution
Converge/speckit.converge
Tasks to issues/speckit.taskstoissues

If the commands are not installed, print the project setup hint (specify init with the host agent, then specify extension add … when needed) and stop. If specify is missing but commands exist, hand off the commands and note the CLI is unavailable.

Rules

  • Never modify .specify/, specs/, or spec-kit extensions.
  • Never model requirements/tasks as a graph.
  • Mapkeeper reads spec.md and tasks.md only to extract IDs and file mentions for links and status counts, not to re-run /speckit.analyze.

Links input

  • spec.md: FR-###, NFR-###, SR-###, CR-### requirement IDs.
  • tasks.md: - [ ] T### … lines, referenced requirement IDs, and mentioned file paths.
  • File mentions are normalized relative paths; specs/, .specify/, project-map/, .mapkeeper/, and graphify-out/ are ignored.

security-audit

Source

security-audit owns audit methodology, sandbox rules, candidate validation, and reports. Mapkeeper routes to it and reads a finished run for links. It never runs phases itself.

Detection

  • Skill: security-audit under project or global skill dirs.
  • Last run: recorded in .mapkeeper/state.json; otherwise pass --run <dir>.
  • Run artifacts: run-metadata.json, findings.json, coverage-ledger.json, REPORT.md, FINDINGS-DETAIL.md, NEEDS-VALIDATION.md, architecture.md.

State records skill, skill_dir, last_run, run_status, findings, source_ref, run_id.

Modes

ChoiceBehavior
Guidance (default)Invoke the skill for a focused question or review. No run directory required.
Full auditOnly on an explicit request. Ask for an output directory outside the target, profile, and budget, then invoke the skill. Its sandbox and validation rules are authoritative.
Existing runRecord the directory for links with mapkeeper links --run <dir>; do not re-audit.

Never auto-run a full audit from the menu, and never relax the skill's execution policy.

Rules

  • Never ingest findings into a graph, re-validate candidates, or rewrite a run directory.
  • Never publish rejected candidates or assign severity to needs_validation.
  • Never copy finding titles or descriptions into link reports; reports use fingerprints, files, requirement IDs, severities, and verdicts.
  • Validation stays in the provider: use its validate-findings.cjs and validate-coverage-ledger.cjs if validation is requested.

Links input

findings.json records with fingerprint/id, verdict, file/path, requirements (or requirement_ids/spec_refs), and severity. Tolerated shapes: an array, or an object with findings, records, results, or items. Rejected records are counted but not linked.

Links report

Source

mapkeeper links reads native outputs and emits a cross-reference report. It does not create a graph or re-extract anything.

Inputs

ProviderDefaultOverride
Graphifygraphify-out/graph.json--graph <path>
spec-kitactive feature from .specify/feature.json, else newest specs/*/spec.mdedit feature.json
security-auditlast run in .mapkeeper/state.json--run <dir>, --no-security

Partial input is allowed. Missing providers are recorded in inputs and warnings; nothing is fabricated. If no input exists at all, the CLI exits 1 and writes no report.

Link types

TypeFrom → toEvidence
finding_filefinding fingerprint → file path, with matching Graphify node IDsfindings.json#<fp>
finding_requirementfinding fingerprint → requirement IDfindings.json#<fp>
requirement_taskrequirement ID → task IDtasks.md#T###
task_filetask ID → file pathtasks.md#T###
requirement_filerequirement ID → file path, derived through taskstasks.md#T###

Rules:

  • Files match by normalized relative path only; no fuzzy label matching.
  • Requirement IDs normalize to FR-001, NFR-001, SR-001, CR-001.
  • Rejected findings are counted but never linked. needs_validation findings are linked without severity.
  • Graph node IDs are preserved verbatim; Mapkeeper invents none.
  • Findings without a file, files without a Graphify node, unknown requirements, requirements without tasks, and missing task files are unresolved.

Freshness

Warnings are added when evidence exists:

  • security source_ref differs from the current revision;
  • Graphify cache mtime is older than the latest commit;
  • spec feature files are older than the latest commit.

No freshness claim is made for non-git directories.

Status and state

Source

mapkeeper status detects the three providers and records local provenance. It never runs a provider.

skill_dir is relative to the project when the skill is inside it, otherwise absolute. last_run is absolute and local only.

Detection

  • Graphify: skill directories, graphify --version, graphify-out/ artifacts.
  • spec-kit: specify --version, .specify/, active feature, installed speckit.*.md commands, extension hooks.
  • security-audit: skill directories plus the last run recorded in state.
  • Legacy: project-map/graph.json and its schema version.

Detection is presence-based. It does not validate provider content beyond what status --check explicitly parses.

Staleness

Warnings only, never failures:

  • security source_ref differs from the current revision;
  • Graphify cache mtime is older than the latest commit;
  • spec feature files are older than the latest commit.

Non-git directories report worktree and skip commit comparisons.

Output

mapkeeper status            # human summary
mapkeeper status --json     # { state, checks: { failures, warnings } }
mapkeeper status --check    # exit 1 on unreadable/invalid present artifacts

--check failures are limited to broken present artifacts (invalid Graphify JSON, invalid findings.json). Missing providers and stale artifacts are warnings.

Troubleshooting

Source

A provider is not detected

status prints hints; Mapkeeper never installs anything.

ProviderTypical fix
GraphifyInstall the graphify skill or CLI, then run /graphify; a cache alone still enables links
spec-kitInstall specify, run specify init for this project, then install the /speckit.* commands for your agent
security-auditInstall the security-audit skill; full audits need an output directory outside the target

spec-kit commands are missing

status reports “initialized but no speckit.* commands”. Initialize the project with specify init and select the current agent, or add the commands to .kilo/commands/ (spec-kit's Kilo integration uses that directory). Mapkeeper will not recreate them.

/mapkeeper spec … only prints a command

That is intentional. An agent cannot execute another slash command. Run the printed /speckit.* command, then return to /mapkeeper links or status.

“no inputs found”

There is no graphify-out/graph.json, no .specify/ feature, and no security run. Build a Graphify cache, initialize spec-kit, or pass --run <dir>. No report is written.

Invalid Graphify cache

status --check fails and links adds invalid_graph when graphify-out/graph.json is not valid JSON. Re-run /graphify --update. Mapkeeper does not repair provider output.

Invalid findings

findings.json exists but cannot be parsed. Use the security-audit skill's own validator and regenerate the run. Mapkeeper does not rewrite or re-validate a run.

Links are missing

Check unresolved first:

  • finding_no_graph_node — Graphify did not index that file; update the graph.
  • finding_unknown_requirement — the finding references a requirement absent from the active feature.
  • requirement_no_task — tasks.md does not mention the requirement.
  • task_missing_file — the task references a path that does not exist.
  • task_unknown_requirement — the task references an ID not in spec.md.

Reports are stale

links warns when the security run revision, Graphify cache, or spec files predate the latest commit. Refresh the relevant provider. Warnings do not fail --check; only broken link targets do.

Security findings are absent from a published report

Local reports include fingerprints, files, severities, and verdicts but never titles, descriptions, or absolute run paths. If security was skipped, check --no-security or whether a run is recorded.

Legacy project-map/ detected

v3 does not read or write v2 artifacts. They are inert history. Archive or delete them manually; status will keep warning until they are gone.

mapkeeper command not found

Run the CLI from the skill checkout:

node scripts/mapkeeper.mjs status

or install the bin with npm link from the skill directory. The /mapkeeper slash command is separate: copy command/mapkeeper.md into ~/.config/kilo/command/ or .kilo/command/.

The /mapkeeper command is missing from the palette

Kilo loads commands at session start. Start a new session or reload after installing command/mapkeeper.md.
